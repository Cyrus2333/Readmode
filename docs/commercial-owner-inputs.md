# Readmode 商业化负责人输入表

这份表用于把“可以商业化”切换成“可以公开售卖”。插件运行时仍保持纯前端；以下信息只用于静态官网、购买入口、支持和许可证签发，不会进入文档处理链路。

## 必须确认的 7 项

| 项目 | 需要提供的值 | 影响 |
| --- | --- | --- |
| 公开官网 | `https://...` | 官网、隐私政策、Pro 页面和设置页链接 |
| 支持入口 | 邮箱或 issue tracker URL | Chrome Web Store 支持地址、插件设置页、帮助页 |
| 支付入口 | 第三方 checkout URL | 设置页和官网的购买按钮；未配置时不会显示购买入口 |
| 销售地区/货币 | 例如“中国大陆 / CNY”或“全球 / USD” | 价格、税务、退款和支付平台选择 |
| Pro 价格 | 一次性授权金额 | 官网、支付页和售后话术 |
| 授权规则 | 例如“个人永久授权，允许 2 台设备使用” | 许可证签发 payload 和客服处理规则 |
| 退款规则 | 退款期限与退款后的授权处理 | 条款页和人工售后流程 |

## 推荐首发决策

- **收费形态**：一次性购买，不做订阅。
- **交付形态**：第三方支付完成后，人工核对订单并发送离线签名激活码。
- **许可证**：不绑定设备、不收集设备指纹；退款后停止后续版本授权，早期不做在线撤销。
- **支付平台**：优先选择能够提供 hosted checkout、订单通知、收据/税务能力和邮件交付的平台。不要把支付密钥、Webhook 密钥或许可证私钥放进扩展。
- **官网部署**：GitHub Pages、Cloudflare Pages 或任意静态托管均可。它不是插件运行依赖；官网不可用时，插件仍应能阅读文档。

## 收到信息后的落地顺序

1. 使用 `npm run commercial:configure -- --site-url <官网> --support-url <支持入口> --payment-url <支付 checkout>` 写入三个公开 URL；脚本不会接受私钥或支付密钥。
2. 生成生产许可证密钥，并把公钥写入 `src/pro/license.js`；私钥放在项目目录之外的安全位置。
3. 用 `npm run release:check` 做严格商业化检查。
4. 用 `npm run package` 构建最终 ZIP，并保存 SHA-256 校验值。
5. 用干净 Chrome 配置文件安装 ZIP，完成购买入口、许可证激活、退款后处理和文档回归。
6. 从最终 Chrome 版本截取商店截图后再提交 Chrome Web Store。

## 当前明确不需要

- 文档云存储；
- 账号系统；
- 在线 license server；
- 支付 Webhook；
- GitHub Pages 作为插件运行时依赖；
- 任何文档内容上传或用户行为分析服务。
